# Работа с VB Accounter

Плагин ведёт локальный реестр обязательств: что сдавать и платить, чего не хватает, какие подтверждения получены и что требует внимания. Это MVP поверх данных VB Accounting, а не перенос всей бухгалтерии. Он не подаёт отчёты в госорганы и не выполняет банковские платежи.

## Подключение

Скажите: «Подключи данные из `/полный/путь/vb-accounting.json`». Нужен файл VB Accounting формата v6, выбранный вами. Плагин читает его без изменений. Он не ищет файлы на диске и не открывает приложение.

Можно начать с новой компании: «Создай компанию „Пример“, режим пока неизвестен». Плагин сохранит её в своём реестре. Неизвестные реквизиты и условия следует уточнить позже.

Примеры вызовов MCP; пространство имён инструмента задаёт хост:

```text
vb_status {}
vb_connect_workspace {"path":"/полный/путь/vb-accounting.json"}
vb_create_company {"name":"Пример","taxRegime":"unknown"}
vb_update_company {"accountId":"company-id","taxRegime":"general","hasEmployees":true}
vb_list_obligations {"horizonDays":31,"includeClosed":false,"includeDemo":false}
vb_get_obligation {"accountId":"company-id","id":"obligation-id"}
```

Позже можно сказать: «У нашей локальной компании теперь известны общий режим и наличие сотрудников». `vb_update_company` принимает `accountId` и изменяемые `name`, `bin`, `taxRegime`, `registrationDate`, `hasEmployees`. Он заполняет факты только локальных профилей; профили подключённого источника остаются доступными для чтения и меняются в исходном приложении.

## Вопросы и состояния

Попробуйте: «Что сдавать в ближайший месяц?», «Что просрочено?», «Чего не хватает для сдачи?», «Что требует моего внимания по этой компании?».

| Измерение | Значение |
|---|---|
| Применимость | `required` — требуется; `unknown` — нужно выяснить; `not-required` — не требуется по зарегистрированным сведениям |
| Отчёт | `needs-data` — нужны данные; `prepared` — подготовлен; `sent` — отправлен; `accepted` — принят по документу; `rejected` — отклонён |
| Платёж | `pending` — ожидает выполнения; `paid` — оплачен по документу |
| Проверка | `pending` — ожидает выполнения; `done` — выполнена |
| Срочность | Вычисляется отдельно по сроку; отсутствие даты не означает отсутствие обязательства |

Принятый отчёт не подтверждает оплату. Отправленный отчёт ещё может ожидать приёма. Пустой реестр, ошибка источника или неизвестная применимость не означают, что компании ничего не нужно сдавать. Демо-записи исключены из обычных запросов и уведомлений; при явном включении они должны быть обозначены.

Встроенный календарь содержит снимок правил. Перед юридическим выводом о сроке и применимости помощник должен проверить актуальный официальный источник. Если проверка недоступна, он показывает зарегистрированные данные с оговоркой. Плагин не гарантирует полный охват обязательств компании.

## Добавление и подтверждения

Скажите: «Добавь проверку необходимости отчёта за квартал», «Проверил назначение: этот отчёт требуется, вот основание и срок», «Не требуется по указанному основанию», «Отметь отчёт отправленным» или «Отметь принятым по этой квитанции».

```text
vb_add_obligation {"accountId":"company-id","title":"Отчёт за квартал","authority":"Уточнить получателя","period":"IV квартал 2026","kind":"filing","applicability":"unknown","notes":"Проверить применимость и официальный срок"}
vb_set_applicability {"accountId":"company-id","id":"obligation-id","applicability":"required","due":"2027-01-15","notes":"Пример: пользователь подтвердил применимость и срок по предоставленному основанию; нужна сверка с официальным источником"}
vb_update_obligation {"accountId":"company-id","id":"obligation-id","status":"sent","notes":"Отправлено пользователем"}
vb_update_obligation {"accountId":"company-id","id":"obligation-id","status":"accepted","evidencePath":"/полный/путь/receipt.pdf"}
```

`vb_set_applicability` переводит неизвестную применимость в `required` или `not-required` либо возвращает её в `unknown`. Для `required`/`not-required` нужно основание: `notes`, `sourceUrl` или `evidencePath`. Необязательный `due` регистрирует срок в формате `YYYY-MM-DD`; `sourceUrl` позволяет сохранить официальный источник срока. Дата в примере условная. Уточнение применимости не подтверждает исполнение.

Для `accepted` обязателен существующий файл квитанции, для `paid` — файл подтверждения платежа. Само наличие файла не проверяет его подлинность или статус в госоргане. Сообщение пользователя и сохранённая применимость/статус не равны государственной проверке. Все эти изменения реестра плагина хранятся локально и отдельно, не перезаписывая исходный файл приложения.

## Напоминания

```text
vb_notification_settings {}
vb_notification_settings {"enabled":true,"leadDays":[14,7,3,1,0]}
vb_list_notifications {"accountId":"company-id","unreadOnly":true,"includeDemo":false}
vb_check_notifications {"accountId":"company-id","includeDemo":false}
vb_ack_notification {"id":"notification-id"}
vb_ack_notification {"id":"notification-id","snoozeUntil":"2026-11-10"}
```

«Покажи уведомления» читает сохранённый список через `vb_list_notifications`, не создавая событий и не отмечая их прочитанными. Можно добавить `accountId`, а `unreadOnly:false` включает прочитанные уведомления. Новая проверка через `vb_check_notifications` создаёт события и сохраняет историю для подавления повторов об одном состоянии. Отметка прочтения не закрывает обязательство. Отсрочка напоминания принимает дату `YYYY-MM-DD` и не изменяет крайний срок.

Без отдельного задания проверка выполняется только при вызове инструмента. Установка плагина и включение уведомлений не создают расписание или системные push-уведомления.

Если нужны проверки по расписанию, попросите об этом явно. Помощник использует инструменты автоматизаций хоста, если они доступны. Заданию нужен тот же постоянный каталог состояния, который показывает `vb_status`; его следует держать вне кэша установленного плагина. Локальный компьютер и хост должны работать, иначе локальное задание не выполнится. Для работы при выключенном компьютере нужен отдельный постоянно работающий сервис; этот MVP его не устанавливает.

Полезное расписание сообщает только о новых значимых действиях, изменениях или ошибках; при неизменном состоянии молчит. Ошибку чтения данных и неизвестную применимость нельзя превращать в сообщение «всё выполнено».

## Данные

MCP-сервер сам не отправляет бухгалтерские данные внешним сервисам. Результаты вызовов инструментов передаются модели через хост для ответа в чате. Учитывайте это при выборе подключаемого источника и подтверждающих документов. Сохраняйте постоянный каталог состояния и файлы подтверждений доступными для будущих проверок.
