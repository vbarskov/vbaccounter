# VB Accounter

Плагин для Kimi Code, Codex и DeepSeek Harness: что нужно сдать и оплатить, каких документов не хватает и что требует внимания. Хранит состояния отчётов, подтверждения и историю уведомлений между чатами. Иконка взята без изменений из VB Accounting.

## Установка

Нужен Node.js 22 или новее. Установка npm-пакетов и сборка не нужны. Проверить версию можно командой `node --version`.

### Kimi Code

Kimi Code устанавливает плагины из GitHub по HTTPS и не принимает SSH-URL как источник установки. Для приватного репозитория сначала клонируйте его через SSH, затем установите локальный каталог:

```sh
git clone git@github.com:ВЛАДЕЛЕЦ/vbaccounter.git
cd vbaccounter
```

В чате Kimi Code выполните:

```text
/plugins install /полный/путь/vbaccounter
/reload
```

Вместо команды можно открыть `/plugins`, перейти на вкладку **Custom** и указать тот же локальный путь. После установки напишите «Настрой VB Accounter». Манифест `kimi.plugin.json` подключает Skills и MCP-сервер автоматически.

Kimi Code копирует плагин в свой управляемый каталог, поэтому изменения исходного репозитория не применяются сами. Для обновления выполните `git pull` в исходном каталоге, повторите `/plugins install /полный/путь/vbaccounter`, затем `/reload`.

#### Запуск MCP на удалённой машине через SSH

Это отдельная возможность: репозиторий можно клонировать по SSH и при этом запускать MCP локально. Удалённый запуск нужен, когда данные и состояние должны находиться на другой машине.

1. Настройте беспарольный вход по ключу и алиас `vbaccounter-host` в `~/.ssh/config`. Проверьте `ssh vbaccounter-host node --version`: на удалённой машине также нужен Node.js 22 или новее.
2. Добавьте SSH-окружение в `~/.kimi-code/config.toml` (или `$KIMI_CODE_HOME/config.toml`):

   ```toml
   [environments.vbaccounter-ssh]
   type = "ssh"
   host = "vbaccounter-host"
   defaultCwd = "/home/ВАШ_ПОЛЬЗОВАТЕЛЬ"
   ```

   Имя `vbaccounter-ssh` должно совпадать с `environment_id` в `kimi.plugin.json`. `host` — алиас из SSH-конфигурации, а не обязательно DNS-имя.
3. В Kimi Code отключите локальный сервер и включите удалённый:

   ```text
   /plugins mcp disable vbaccounter vbaccounter
   /plugins mcp enable vbaccounter vbaccounter-ssh
   /reload
   ```

4. Проверьте подключение через `/mcp`, затем попросите: «Покажи статус VB Accounter».

SSH-вариант выключен по умолчанию, поэтому без настройки окружения плагин работает локально. Не включайте оба сервера одновременно: они предоставляют одинаковые операции под разными MCP-именами.

При удалённом запуске пути к `vb-accounting.json`, квитанциям и платёжным подтверждениям должны существовать **на удалённой машине**. Каталог состояния по умолчанию также находится там. Чтобы задать его явно, добавьте в описание `vbaccounter-ssh` внутри установленного манифеста `env` с абсолютным `VBACCOUNTER_DATA_DIR`, либо используйте отдельную конфигурацию MCP из следующего раздела.

Для возврата к локальному запуску отключите `vbaccounter-ssh`, включите `vbaccounter` и выполните `/reload`.

#### Подключение без установки плагина

Можно добавить только MCP в `~/.kimi-code/mcp.json`:

```json
{
  "mcpServers": {
    "vbaccounter": {
      "command": "node",
      "args": ["/полный/путь/vbaccounter/scripts/mcp-server.mjs"],
      "cwd": "/полный/путь/vbaccounter"
    }
  }
}
```

Для SSH добавьте `"environment_id": "vbaccounter-ssh"` и удалённые пути в `args` и `cwd`. После изменения создайте новый чат. В этом варианте Skills плагина не устанавливаются.

### Codex

В каталоге репозитория есть локальный marketplace `.agents/plugins/marketplace.json`. Добавьте его в Codex CLI:

```sh
codex plugin marketplace add /полный/путь/vbaccounter
```

Затем выберите источник «VB — локальные плагины» в каталоге плагинов настольного Codex и установите **VB Accounter**. Начните новый локальный чат с запросом «Настрой VB Accounter». Пакет не устанавливает себя и не меняет глобальные настройки.

Для другого MCP-клиента укажите `node` и абсолютный путь к `scripts/mcp-server.mjs` как аргумент. Конфигурации `mcp.json` и `.mcp.json` поддерживают переносимый формат и совместимость Codex соответственно.

### DeepSeek Harness

В `package.json` объявлен `dsh.bundle.patch`, поэтому профиль DSH получает три навыка из `skills/` как bundled-провайдеры. MCP-сервер запускается отдельным процессом, и его путь зависит от машины, поэтому строку профиля добавляет скрипт.

Нужны Node.js 22 или новее (как и для остальных хостов) и установленное приложение DeepSeek Harness. Ниже используется профиль `desktop`; для Web-профиля замените его на `web`.

1. Возьмите каталог пакета — клонированный репозиторий. Дальше `/полный/путь/vbaccounter` означает его абсолютный путь.
2. Подключите навыки в профиль (`link:` не копирует файлы, правки в каталоге видны сразу):

   ```sh
   DSH="/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh"
   "$DSH" plugin --profile desktop add link:/полный/путь/vbaccounter
   ```

3. Добавьте MCP-сервер `vbaccounter` в профиль:

   ```sh
   node /полный/путь/vbaccounter/dsh/install-mcp.mjs
   ```

4. Перезапустите DeepSeek Harness и начните новый чат: в каталоге навыков появятся `vb-setup`, `vb-obligations`, `vb-reporting`, а инструменты — с именами `vb_*`.
5. Подключите данные: «Настрой VB Accounter» или укажите путь к `vb-accounting.json` для `vb_connect_workspace`. Каталог состояния общий с остальными хостами.

Навыки названы с префиксом `vb-`, потому что DSH хранит навыки всех плагинов в одном пространстве имён: без префикса навык `setup` спорил бы с плагином MCU iOS Git Flow, и один из двух был бы вытеснен.

`dsh/install-mcp.mjs` правит `~/.dsh/profiles/desktop/cordis.patch.yml` (другой профиль — `--profile`, другой корень — `DSH_HOME`), не трогает чужие строки, заменяет свой блок при повторном запуске и умеет показать его без записи: `--print`.

Обновление: выполните `git pull`, повторите шаги 2–3 и начните новый чат. Удаление: `"$DSH" plugin --profile desktop remove vbaccounter` и блок `mcp-vbaccounter` из `cordis.patch.yml`.

## Данные и состояния

Можно создать профиль ТОО в плагине или явно подключить `vb-accounting.json` версии 6. Плагин перечитывает выбранный файл при запросах и **не записывает в него**. Свои статусы, документы и уведомления хранит отдельно от приложения и установленного кеша плагина. Автоматического поиска личных файлов нет.

Результат «требуется / не требуется» и установленный срок можно сохранить с основанием через `vb_set_applicability`. История уведомлений доступна через `vb_list_notifications` и в новом чате.

Неизвестные сведения локальной компании можно дополнить через `vb_update_company`: режим, дату регистрации и наличие работников. Подключённые карточки приложения остаются доступными только для чтения.

Применимость, состояние подготовки/сдачи, состояние оплаты и срочность учитываются отдельно. Для «принят» нужен файл квитанции, для «оплачен» — файл подтверждения оплаты. Сохранённый файл с хешем подтверждает, какие сведения предоставил пользователь; плагин не проверяет статус в государственном кабинете.

По умолчанию каталог состояния:

- macOS: `~/Library/Application Support/VB Accounter`;
- Windows: `%LOCALAPPDATA%/VB Accounter`;
- Linux: `${XDG_DATA_HOME:-~/.local/share}/vbaccounter`.

Его можно явно изменить через `VBACCOUNTER_DATA_DIR` или `--data-dir /absolute/path`. Используйте один и тот же каталог в обычных чатах и заданиях по расписанию. Резервная копия должна включать весь этот каталог с подтверждающими документами.

Ограничение входного файла приложения — 50 МиБ, одного подтверждающего документа — 10 МиБ.

Сервер не подключается к сети. Результаты инструментов передаются модели в текущем чате; это не означает, что данные остаются только внутри процесса MCP.

## Напоминания

«Проверь, что требует моего внимания» вызывает `vb_check_notifications`: новые события сохраняются с защитой от повторов. Прочтение или откладывание уведомления не закрывает обязательство и не переносит срок.

Фоновые проверки создаются отдельно через задания Codex по явному запросу пользователя. Сам сервер не запускает таймеры, не отправляет push, письма и сообщения. Локальное задание требует включённого компьютера, доступного файла данных и работающего хоста Codex. Для уведомлений при выключенном компьютере нужен отдельный постоянно работающий сервис.

## Покрытие первой версии

Используется снимок чистых расчётных модулей VB Accounting: ФНО 910.00/200.00, назначения БНС и Нацбанка, проверки документов и зарплатных платежей. Дополнительные обязанности можно добавить вручную. Это не полная система бухучёта и не полный перечень применимых форм. Для общего или неизвестного режима автоматического налогового календаря пока нет.

Источники и сроки из приложения сохраняются с признаком необходимости проверки действующих правил. Для будущих периодов дата может быть ориентиром. Список без найденных задач не подтверждает отсутствие юридических обязанностей. Подача отчётов, ЭЦП, платежи и синхронизация статусов обратно в приложение в эту версию не входят.

Примеры работы и семантика инструментов: [docs/USAGE.md](docs/USAGE.md). Происхождение расчётных модулей: [vendor/PROVENANCE.md](vendor/PROVENANCE.md).

```sh
node --test tests/*.test.mjs
```

Тесты используют временные данные, проверяют MCP по stdio, сохранение состояния, подтверждения, уведомления и отсутствие изменений в подключённом файле приложения. GUI, Electron и DerivedData не используются.
