# Подключение VB Accounter

Используй инструменты MCP плагина по именам `vb_*`; префикс пространства имён зависит от хоста.

1. Вызови `vb_status`, чтобы узнать источник и каталог постоянного состояния.
2. Если пользователь выбрал существующие данные, передай точный путь к файлу формата v6 `vb-accounting.json` в `vb_connect_workspace {"path":"/полный/путь/vb-accounting.json"}`. Если путь не указан, запроси его. Не ищи личные файлы по диску и не открывай исходное приложение или GUI.
3. Для новой компании вызови `vb_create_company` с `name` и известными полями `bin`, `taxRegime` (`simplified`, `general`, `unknown`), `registrationDate`, `hasEmployees`. Не угадывай режим, дату регистрации или наличие сотрудников; неизвестный режим — `unknown`.
4. Проверь результат через `vb_status`. Назови подключённый источник или созданную компанию и следующий доступный сценарий: «Что сдавать в ближайшие 31 день?».
5. При первичной настройке предложи ежемесячные резервные копии юрлица в Telegram. Покажи выбор бота по умолчанию, своего бота или возможность пропустить этот шаг. Для запроса только на изменение реквизитов или напоминаний этот шаг не нужен.

Когда пользователь уточнит данные локальной компании, вызови `vb_update_company` с `accountId` и изменёнными известными полями: `name`, `bin`, `taxRegime` (`simplified`, `general`, `unknown`), `registrationDate`, `hasEmployees`. Например, «теперь известно: общий режим, есть сотрудники» позволяет заполнить эти два поля, сохранив остальные. Не подменяй неизвестные факты догадками. Инструмент меняет только локальные профили; реквизиты компании из подключённого источника нужно исправлять в исходном приложении.

Исходный файл приложения доступен только для чтения. Компании и изменения плагина хранятся отдельно. Подключение не переносит в плагин все функции бухгалтерского приложения и не подтверждает полноту обязательств.

## Резервные копии в Telegram

1. Вызови `vb_status` и `vb_backup_settings {}`. Предложи выбрать юрлицо по названию и БИН из `availableCompanies`. Каждый архив и расписание относятся к одному БИН. Проверь `configuredCompanies` и `defaultBotAvailable`. Покажи `defaultBotUsername`, если оно задано. Если общий бот недоступен, предложи своего бота или возможность пропустить этот шаг.
2. Запроси положительный `chat_id` личного чата и открытый ключ age с префиксом `age1`. Закрытый ключ остаётся у пользователя и должен быть доступен отдельно от компьютера с бухгалтерией. Для общего бота вызови `vb_backup_pair {}`, передай пользователю полученную ссылку `url` и попроси открыть её и нажать Start. Для своего бота попроси нажать Start в личном чате, покажи `ownBotTokenPath` и направь пользователя к локальной настройке токена по [руководству](../../docs/USAGE.md#резервные-копии-в-telegram). Токен своего бота пользователь сохраняет локально.
3. Сохрани настройки вызовом `vb_backup_settings {"bin":"123456789012","bot":"default","chatId":"123456789","recipient":"age1…"}`, подставив БИН и реквизиты пользователя. Для своего бота передай `"bot":"own"`. В копию входят данные и документы выбранного юрлица. При отсутствии подключения используется стандартный путь VB Accounting на macOS. Если файл находится в другом месте, подключи указанный пользователем файл через `vb_connect_workspace`.
4. Проверь `ready` через `vb_backup_settings {"bin":"123456789012"}` для выбранного БИН и доступность `age` на компьютере с данными. Для общего бота привязку проверяет `vb_backup_settings`. Для своего проверь `tokenReady`. Готовность источника проверь по `accountingReady`. После согласия на ежемесячную отправку создай отдельное задание для выбранного БИН через инструмент автоматизаций хоста. Укажи время и часовой пояс пользователя, каталог данных из `vb_status` и вызов `vb_send_backup {"bin":"123456789012"}` с выбранным БИН. Если время не указано, предложи первое число месяца в 10:00 по местному времени. Если несколько юрлиц отправляют копии общим ботом в один чат, разнеси задания по времени. Хост и компьютер должны работать. При отсутствии инструмента автоматизаций оставь ручной запуск по просьбе пользователя.

Если пользователь просит отправить первую копию сразу, вызови `vb_send_backup` с БИН. Если Telegram не подтвердил доставку, попроси проверить личный чат. Повторяй с тем же БИН и `"retryUnconfirmed":true` по просьбе пользователя после такой проверки. Для отключения вызови `vb_backup_settings` с БИН и `"bot":"disabled"`. Отключи расписание этого юрлица, если оно было создано.

## Уведомления

Для уведомлений об обязательствах по просьбе пользователя настрой `vb_notification_settings {"enabled":true,"leadDays":[14,7,3,1,0]}`; без параметров инструмент показывает текущие настройки. Для «покажи уведомления» используй `vb_list_notifications {"unreadOnly":true,"includeDemo":false}` с необязательным `accountId`: это чтение сохранённого списка без создания событий. `vb_check_notifications` выполняет новую проверку при вызове и сохраняет историю для подавления повторов.

Задание по расписанию создавай только по прямой просьбе пользователя и через доступные инструменты автоматизаций хоста. В задании укажи реальный постоянный каталог состояния из `vb_status`, общий с интерактивными вызовами и расположенный вне установленного кэша плагина. Локальный компьютер и хост должны работать. Уведомлять следует о новых значимых действиях, изменении срока/состояния, отказе чтения данных или необходимом уточнении; при неизменном состоянии — молчать. Не выдавай ошибку источника или неизвестную применимость за «всё сдано».

Если автоматизации хоста недоступны, объясни ограничение и оставь проверку по запросу. Не записывай выдуманную конфигурацию расписания и не обещай фоновую работу после закрытия хоста.
