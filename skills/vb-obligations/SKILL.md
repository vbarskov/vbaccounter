# Что требует внимания

Начни с `vb_status`. Если компании нет, попроси пользователя указать файл v6 `vb-accounting.json` для `vb_connect_workspace {"path":"…"}` или данные новой компании для `vb_create_company`. Не сканируй диск и не открывай GUI.

Вызови `vb_list_obligations` с подходящими параметрами:

```json
{"horizonDays":31,"includeClosed":false,"includeDemo":false}
```

Добавь `accountId`, если пользователь выбрал компанию. При неоднозначности уточни компанию. Для вопроса об отдельном обязательстве используй `vb_get_obligation {"accountId":"…","id":"…"}`. Для «покажи уведомления» используй `vb_list_notifications {"unreadOnly":true,"includeDemo":false}` с выбранным `accountId`: он только читает сохранённые уведомления. Для новой проверки ближайших действий вызови `vb_check_notifications` с выбранным `accountId` и `includeDemo:false`; проверка создаёт новые события и обновляет историю повторов.

Различай три независимых измерения:

- Применимость: `required` — требуется, `unknown` — нужно выяснить, `not-required` — не требуется по зарегистрированным данным.
- Исполнение: подготовка/отправка/приём отчёта, оплата или выполнение проверки. Отправка ещё не означает приём, а принятый отчёт не подтверждает оплату.
- Срочность: срок впереди, приближается или истёк. Неизвестный срок не означает отсутствие срока.

Покажи сначала просроченное и ближайшие действия, затем недостающие данные и вопросы применимости. Для каждого существенного пункта укажи компанию, период, адресата, зарегистрированный срок, источник/основание и следующий шаг. Демо-данные включай только по просьбе и явно помечай.

Локальный календарь — снимок правил, а пользовательские записи — зарегистрированные сведения. Перед выводом о действующей юридической обязанности или официальном сроке проверь актуальные первичные источники доступным веб-инструментом хоста и дай ссылку. Если проверить нельзя, назови срок зарегистрированным и требующим проверки. Не обещай полный охват отчётности и не делай вывод «ничего сдавать не нужно» из пустого списка, ошибки источника или `unknown`.

## Реакция на уведомление

По просьбе пользователя отметь прочитанным/отложи уведомление через `vb_ack_notification {"id":"…"}` или с `snoozeUntil` в формате `YYYY-MM-DD`. Показ списка через `vb_list_notifications` не отмечает его прочитанным. Подтверждение прочтения не закрывает обязательство, отсрочка уведомления не меняет срок сдачи. Настройки доступны через `vb_notification_settings` (`enabled`, массив целых `leadDays`). Не меняй их без соответствующего запроса.

Проверка хранит историю и подавляет повторы, но выполняется только при вызове. Расписание создавай лишь по просьбе пользователя через инструменты автоматизаций хоста, с тем же постоянным каталогом состояния вне кэша плагина. Локальные проверки требуют работающего компьютера и хоста; уведомляй только о новых значимых действиях, изменениях и ошибках, при неизменном состоянии молчи. Без инструмента автоматизаций не обещай автоматическую доставку.
