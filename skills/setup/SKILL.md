# Подключение VB Accounter

Используй инструменты MCP плагина по именам `vb_*`; префикс пространства имён зависит от хоста.

1. Вызови `vb_status`, чтобы узнать источник и каталог постоянного состояния.
2. Если пользователь выбрал существующие данные, передай точный путь к файлу формата v6 `vb-accounting.json` в `vb_connect_workspace {"path":"/полный/путь/vb-accounting.json"}`. Если путь не указан, запроси его. Не ищи личные файлы по диску и не открывай исходное приложение или GUI.
3. Для новой компании вызови `vb_create_company` с `name` и известными полями `bin`, `taxRegime` (`simplified`, `general`, `unknown`), `registrationDate`, `hasEmployees`. Не угадывай режим, дату регистрации или наличие сотрудников; неизвестный режим — `unknown`.
4. Проверь результат через `vb_status`. Назови подключённый источник или созданную компанию и следующий доступный сценарий: «Что сдавать в ближайшие 31 день?».

Когда пользователь уточнит данные локальной компании, вызови `vb_update_company` с `accountId` и изменёнными известными полями: `name`, `bin`, `taxRegime` (`simplified`, `general`, `unknown`), `registrationDate`, `hasEmployees`. Например, «теперь известно: общий режим, есть сотрудники» позволяет заполнить эти два поля, сохранив остальные. Не подменяй неизвестные факты догадками. Инструмент меняет только локальные профили; реквизиты компании из подключённого источника нужно исправлять в исходном приложении.

Исходный файл приложения доступен только для чтения. Компании и изменения плагина хранятся отдельно. Подключение не переносит в плагин все функции бухгалтерского приложения и не подтверждает полноту обязательств.

## Уведомления

По просьбе пользователя настрой `vb_notification_settings {"enabled":true,"leadDays":[14,7,3,1,0]}`; без параметров инструмент показывает текущие настройки. Для «покажи уведомления» используй `vb_list_notifications {"unreadOnly":true,"includeDemo":false}` с необязательным `accountId`: это чтение сохранённого списка без создания событий. `vb_check_notifications` выполняет новую проверку при вызове и сохраняет историю для подавления повторов. Сам плагин не работает постоянно и не создаёт системные push-уведомления.

Задание по расписанию создавай только по прямой просьбе пользователя и через доступные инструменты автоматизаций хоста. В задании укажи реальный постоянный каталог состояния из `vb_status`, общий с интерактивными вызовами и расположенный вне установленного кэша плагина. Локальный компьютер и хост должны работать. Уведомлять следует о новых значимых действиях, изменении срока/состояния, отказе чтения данных или необходимом уточнении; при неизменном состоянии — молчать. Не выдавай ошибку источника или неизвестную применимость за «всё сдано».

Если автоматизации хоста недоступны, объясни ограничение и оставь проверку по запросу. Не записывай выдуманную конфигурацию расписания и не обещай фоновую работу после закрытия хоста.
